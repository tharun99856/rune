# v0.1 Language Freeze

Phase 1 (evidence collection) is over. This document is the freeze marker.

## What was asked, and what the data said

**Question:** does the concept vocabulary stabilize as more problems are
tested, or does it keep growing indefinitely?

```
batch 1 (18 problems):  +10 new concepts  (0.56 per problem)
batch 2 (33 problems):  +5 new concepts   (0.15 per problem)
batch 3 (49 problems):  +1 new concept    (0.02 per problem)
```

100 problems tested. That's the answer, and it's the one the experiment was
designed to be able to give either way. Continuing to 200, 500, 1000 for its
own sake now would be evidence-collection as procrastination, not rigor.

## Grammar as of the original freeze (see below for what's been promoted since)

Four keywords, four concepts, frozen after the 100-problem batch:

```
GROUP <source> BY <key>     -- Grouping
COUNT EACH <noun>           -- Aggregation
ORDER BY <key> [ASC|DESC]   -- Ordering
TAKE <count>                -- Selection
```

`docs/language/grammar/current.md` is kept in sync with the actual parser
and is the up-to-date source of truth for the full keyword list, including
anything promoted after this document was first written.

## Frozen: the concept list (16, from `docs/language/ledger.csv`)

Grouping, Aggregation, Ordering, Selection, Filtering, Stateful Scan,
Ordered Lookup, Relation, Window, Traversal, Enumeration, ADT Definition,
Set Merging, Serialization, Streaming, Construction.

**No new concepts unless something genuinely breaks the model** — a finding
of the shape ABSTRACTION_QUESTIONS.md was built for, not "problem 101 wanted
something new." The atlas, ledger, and research journal stay open for
correction (mistags, like Validate BST, get fixed) but not for expansion.

## Frozen: the atlas and research journal

`docs/language/atlas/`, `docs/language/research/`, and
`docs/language/primitives/candidates/` are historical record from here.
Reference them; don't extend them by default.

## Promoted since the freeze: Traversal (`EXPLORE`)

This document said "no new concepts unless something genuinely breaks the
model." Traversal was promoted anyway, and the honest thing is to say so
here explicitly rather than let this file quietly go stale — which is
exactly what happened for a few commits before this correction.

**Evidence, not a mood:** Traversal had 24 problems in the ledger by the
time it was promoted (second only to Stateful Scan's 34), and unlike
Stateful Scan it held up as *one* coherent concept across trees, grids, and
graphs with no internal splitting needed — see
`docs/language/primitives/candidates/graph-traversal.md`. That's a
materially stronger case than "it seemed useful."

**What it unlocked:** the second optimizer proof (BFS vs. Dijkstra,
selected at runtime from the graph's actual data, not from syntax) — a
different *kind* of proof than `TOP_K`, which is what made it worth
promoting now rather than waiting for a rounder number of problems.

Grammar is now five keywords, five concepts. Stateful Scan (34 problems,
still internally unresolved — see
`docs/language/research/2026-07-08-stateful-scan-split.md`) remains the
next candidate, deliberately not promoted alongside Traversal — one
promotion at a time, not a batch.

## What's NOT frozen: Phase 2

Implementation, in this order: finish the parser for concepts that clear
promotion (case by case, not "add 20 keywords at once"), an optimizer that
recognizes compositions and rewrites them to better implementations, then a
backend, with an AI recovery layer last, not first.

**First optimizer target, because it needs zero new grammar:** `ORDER DESC
+ TAKE k` recognized and rewritten to a heap-based top-k selection. Both
`ORDER` and `TAKE` are already in the frozen grammar — this proves the
optimizer's value without touching anything that was just frozen.
