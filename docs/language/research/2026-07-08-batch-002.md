## Pain points / Candidate capabilities

**Stateful Scan is now 19/51 — a 2.7x lead over the next candidate
(Traversal, 11).** This isn't new evidence of a new capability; it's
overwhelming confirmation of the existing candidate, and probably now clears
whatever bar "yesterday's 50 problems" was meant to set. Flagging this as
ready for a real decision, not deciding it here.

**Traversal jumped from 2 to 11** with Trees and Graphs added — exactly the
"expect this to climb fast" prediction already written in the candidate
page at the time (since promoted — see `docs/language/primitives/EXPLORE.md`).

**Five genuinely new findings, not just gap counts:**

1. **Enumeration/Backtracking (Subsets, Permutations, N-Queens) — 3
   occurrences, and possibly the first real abstraction question.**
   Backtracking explores a decision tree the algorithm itself builds
   (choose, recurse, undo), not a traversal of a given structure and not a
   forward scan. Logged in `ABSTRACTION_QUESTIONS.md` — nowhere near the
   ~20-problem threshold, but worth watching specifically because, unlike
   Traversal, it's not obvious this even fits "one line transforms the
   previous result" at all.

2. **Serialization (Serialize/Deserialize Binary Tree) — 1 occurrence.**
   Doesn't decompose into anything on the current concept list. Too little
   evidence to do anything with; noted so it isn't rediscovered from zero
   later.

3. **Set Merging (Union-Find / Connected Components) — 1 occurrence.**
   Deliberately not folded into Traversal — Union-Find incrementally merges
   sets rather than walking edges, a different mechanism that happens to
   solve similar-sounding problems. Tagged separately rather than guessed
   into an existing bucket.

4. **Streaming (Find Median from Data Stream) — 1 occurrence, logged in
   `ABSTRACTION_QUESTIONS.md`.** This is the sharpest finding in the batch.
   Every current concept assumes a complete input up front; a streaming
   algorithm processes one element at a time with no defined "end." This
   isn't a missing keyword — it's a case where the whole pipeline premise
   (`source → transform → transform → result`) may not apply at all.

5. **ADT Definition (Implement Trie, Min Stack) — 2 occurrences, also
   logged in `ABSTRACTION_QUESTIONS.md`.** These aren't algorithms over data
   — they're requests to define a stateful object with named operations
   (insert/search, push/pop/getMin). Structurally closer to "define a small
   API" than "express a transformation." Possibly permanently out of scope
   (see `docs/language/ANTI_GOALS.md`) rather than a capability gap at all.

**Minor, separate finding:** Single Number and Number of 1 Bits (bit
manipulation) are tagged `SUGAR`, not `GAP` — they fit the existing
Aggregation concept, they'd just need a wider set of reduction operators
(XOR, popcount) than today's grammar happens to expose. Worth remembering
this is a sugar/operator-set question, not a new concept question, when
Aggregation's operator list eventually gets revisited.

## Rejected capabilities

Did not fold Union-Find into Traversal, and did not fold Streaming or ADT
Definition into any existing concept, purely to hit a rounder number of
buckets. Under-merging felt safer than over-merging here, consistent with
the correction already made once this session (First-Unique vs.
Contains-Duplicate).

## Decision

No grammar change. Ledger updated (51 rows total). Two new entries added to
`ABSTRACTION_QUESTIONS.md` (Backtracking, Streaming/ADT-definition) as
categories to watch — not conclusions.

**One decision this entry does NOT make, on purpose:** whether Stateful
Scan's 19-problem lead now clears the evidence bar for implementation. That
requires resolving the still-open sub-question (rolling scalar vs. full
table vs. stack vs. linked-list pointers — is this one primitive or several)
before syntax gets discussed at all, and it's a keyword-naming decision,
which stays outside this session's authority per `CLAUDE.md`.
